# План проекта: Slash Arena (рабочее название)

> Этот документ — единый источник правды по проекту. Его читают и человек, и AI-ассистенты (Claude как архитектор, Cursor как редактор скриптов). Любые изменения архитектуры и роадмапа фиксируются здесь.

---

## 1. О проекте

**Жанр:** ареновый слешер от 3-го лица с волнами врагов.
**Движок:** Unity 6000.2.10f1 (URP).
**Ключевые пакеты:** Input System (новый), Cinemachine 3.x, AI Navigation 2.x, TextMesh Pro.
**Стиль:** low-poly (Blink Humans + PurePoly Weapons + позже добавим CC0-ассеты).

**Цели:**
- Полноценный учебный пет-проект, на котором владелец проходит ключевые концепции геймдева в Unity.
- Возможный релиз на itch.io (минимально достаточный) или Steam (если проект «зайдёт» — потребует доп. фазы полировки и юр. подготовки).
- НЕ MMO, НЕ мультиплеер. Однопользовательский слешер с прогрессией внутри забега.

**Стиль кода и архитектуры:**
- Data-driven: всё, что может быть данными, — это ScriptableObject (оружие, скины, архетипы врагов, конфиги).
- Композиция важнее наследования.
- Минимум `FindObjectOfType` в `Update`, кэшировать ссылки в `Awake`/`Start`.
- `IDamageable` уже есть — расширяем интерфейсами по мере роста (`IInteractable`, `IPickup` и т. д.).

## 2. Команда и роли

| Кто | Что делает |
|---|---|
| **Владелец (человек)** | Принимает решения, делает работу в Unity Editor (расстановка, Animator, Inspector, Prefabs, NavMesh bake), тестирует, играет |
| **Claude (архитектор + Claude Code)** | Дизайн систем, ScriptableObject-модели, согласование структуры папок и публичного API, ревью, обучение концепциям. Через Claude Code — прямые правки кода и YAML-ассетов в репозитории, коммиты |
| **Cursor (in-file editor)** | Быстрые правки внутри уже существующих скриптов: баги, мелкие рефакторинги, добавление методов в рамках согласованного API, форматирование, комментарии |

### Правила взаимодействия с Cursor

Cursor может **сам**:
- править тело методов
- добавлять private-поля и приватные методы
- чинить баги, на которые есть чёткое описание
- рефакторить локально (внутри одного файла)
- добавлять `[SerializeField]` к существующим private-полям

Cursor **должен спросить Claude / владельца** перед:
- созданием новых файлов (особенно ScriptableObject-классов)
- переименованием файлов и публичных классов/методов
- изменением публичного API существующего скрипта (новые public-поля, новые public-методы, изменение сигнатур)
- созданием новых папок или перемещением файлов
- удалением скриптов
- добавлением зависимостей от новых пакетов

### Конвенции, которым следуют ВСЕ (включая Cursor)

1. **Папки:** свой код и ассеты только в `Assets/_Project/`. Папка `Assets/Imported/` — только для покупных/CC0 пакетов, её не трогаем.
2. **Namespace:** пока без namespaces — слишком ранний этап. Введём позже, если разрастётся.
3. **Имена:** PascalCase для классов, методов, properties; camelCase для private-полей; ALL_CAPS для констант.
4. **`[SerializeField] private`** предпочтительнее `public` для полей, которые редактируются в Inspector, но не используются другими скриптами.
5. **`[Header]` и `[Tooltip]`** обязательны на всех видных в Inspector полях, чтобы Editor-работа была понятной.
6. **Логи:** используем `Debug.Log` с префиксом в квадратных скобках (`[Jump]`, `[Spawn]`) — это уже сложилось в проекте, продолжаем.
7. **Без LINQ в `Update`** и горячих циклах (аллокации).
8. **Никаких `GameObject.Find` / `FindObjectOfType` в `Update`** — кэшируем в `Awake`.

## 3. Архитектурные решения (decisions log)

### D1: Data-driven через ScriptableObject
Все игровые данные — отдельные `.asset` файлы:
- `WeaponDefinition` (имя, иконка, префаб, стат-блок, override-аниматор, звук)
- `EnemyArchetype` (HP, скорость, броня, оружие, AI-профиль, drop-таблица)
- `SkinDefinition` (имя, превью, материалы, меш override)
- `GameConfig` (глобальные настройки)

### D2: Структура папок (`Assets/_Project/`)
```
Assets/
├── _Project/                  ← всё своё
│   ├── Animations/
│   ├── Art/
│   ├── Audio/
│   ├── Data/                  ← все ScriptableObject .asset
│   │   ├── Weapons/
│   │   ├── Enemies/
│   │   ├── Skins/
│   │   └── Configs/
│   ├── Editor/
│   ├── Input/
│   ├── Prefabs/
│   ├── Scenes/
│   ├── Scripts/
│   │   ├── Anim/
│   │   ├── Combat/
│   │   ├── Data/              ← классы ScriptableObject
│   │   ├── Debug/
│   │   ├── Enemy/
│   │   ├── Interaction/       ← пикапы, взаимодействия (Фаза 2)
│   │   ├── Player/
│   │   ├── UI/
│   │   └── Util/
│   └── Settings/              ← URP, Render, Quality
├── Imported/                  ← НЕ ТРОГАЕМ (Blink, PurePoly, будущие CC0)
├── Samples/                   ← оставляем как есть
└── TextMesh Pro/              ← оставляем
```

### D3: Сейвы — JSON в `Application.persistentDataPath`
Не `PlayerPrefs` (слишком плоско). Один файл `save.json`, обновляется через типизированный `SaveService`. Структура: settings, leaderboard[], lastSelectedSkin, totalRuns.

### D4: Animator на Humanoid
Модели приводим к Humanoid Avatar — открывает доступ к Mixamo и кросс-совместимым анимациям. Решение принято в Фазе 1.

### D5: Лицензии ассетов
Записываем источник и лицензию каждого нового ассета в этот документ (раздел «Библиотека ассетов»). Особенно важно при возможном релизе на Steam.

### D6: Прыжок удалён из геймплея (2026-07-06)
Слешер строится на перекате, блоке и ударах — прыжок не нужен и выглядел криво. Код прыжка вырезан из `ThirdPersonController`. Экшен `Jump` в Input Actions и стейт `Jump` в аниматоре пока лежат мёртвыми (никем не активируются, не мешают) — можно удалить в редакторе при случае.

### D7: Кор-луп — оружие с прочностью (2026-07-06)
Оружие спавнится по карте, имеет запас прочности и ломается → игрок постоянно ищет новое. Вместе с волнами это главный источник напряжения. `WeaponDefinition` получает поля прочности.

### D8: Волновая структура спавна (2026-07-06)
Вместо непрерывного спавна по таймеру — `WaveManager`: волны с паузами, сложность растёт по номеру волны бесконечно. `EnemySpawner` подчиняется менеджеру волн. Спавн оружия привязан к началу волны.

## 4. Дорожная карта (v2, 2026-07-06)

> Переработана под зафиксированное видение: **(1)** главное меню + гардероб, **(2)** бесконечный слешер с волнами врагов и souls-like боёвкой, **(3)** оружие спавнится по карте и имеет прочность — надо успевать искать новое. Классы персонажей, онлайн и карты — в парковке. Старые «Фазы 0–7» заменены «Этапами 0–5»; их содержимое перенесено внутрь этапов.

Каждый этап: **цель → работы → acceptance**. После каждого этапа — пауза, ревью, плейтест.

### Этап 0 — Стабилизация: «всё работает честно» 🔄 (код готов, идёт проверка)

**Цель:** убрать все места, где механика «выглядит готовой, но не работает».

**Сделано кодом (2026-07-06):**
- Один источник правды для веса UpperBody-слоя: SMB `AttackLayerWeight` удалён из аниматора и проекта, вес ведёт только `ThirdPersonController.UpdateUpperBodyLayerWeight()`.
- Блок по-настоящему: поглощает % урона (`PlayerHealth.blockDamageAbsorb`, по умолчанию 70%), замедляет движение (`blockMoveMultiplier` 0.4), отключает спринт.
- Кик: собственный `HitShape` (`PlayerAttack.kick`), `AttackStrength.Kick`, окно урона в стейте `Kick` переключено на Kick.
- Очки работают: `EnemyHealth.Die()` → `GameManager.RegisterKill()` → `scorePerKill` из `GameConfig`.
- `GameConfig` подключён по-настоящему: `playerStartHealth`, `scorePerKill`, `showDiagnosticsHUD` (ссылки прописаны в сцене).
- `IDamageable` вынесен в свой файл, реализован `PlayerHealth`/`EnemyHealth`; урон везде типизирован (SendMessage убран). Мёртвые `EnemyAtack.cs` и `Hurtbox.cs` удалены.
- Прыжок вырезан из кода (D6); гравитация — обычное сериализуемое поле.
- Рестарт: единый путь через `GameManager.Restart()`, клавиша R работает **только** на экране game over, курсор разблокируется при смерти.
- Производительность: `EnemyAI` пересчитывает путь раз в 0.2 с (вместо каждого кадра), avoidance Medium, урон через кэшированный `IDamageable`; аниматор-проверки без аллокаций (`GetCurrentAnimatorClipInfoCount`); DiagnosticsHUD на NonAlloc и с гейтом в билде.
- Валидатор и DiagnosticsHUD обновлены под актуальные имена параметров/экшенов.

**Осталось (editor-работа владельца):**
- Назначить клип кика в стейт `Kick` (Mixamo → Roundhouse Kick, Humanoid) — сейчас стейт без Motion, кик бьёт «невидимо».
- Прогнать `Tools ▸ SmashArena ▸ Validate Setup`, плейтест золотой петли.
- (опц.) Удалить в редакторе мёртвый стейт `Jump`, экшены `Jump`/`Interact`/`Crouch` не трогаем — пригодятся.

**Acceptance:** бег + спринт + перекат + лёгкий/тяжёлый/кик + блок работают и выглядят правильно; счёт растёт; R в бою ничего не сбрасывает; в Profiler нет GC-аллокаций от Animator в бою.

### Этап 1 — Ощущение боя (game feel + звук)

**Цель:** бой «чувствуется» — враги реагируют, звук наполняет сцену.

**Работы:**
- Хит-реакция врага (флинч-анимация по получению урона) + **анимация смерти** (отключить коллайдер/агент, Destroy с задержкой ~3 с).
- I-frames на перекате: окно неуязвимости в `PlayerHealth`, читающее состояние доджа из `ThirdPersonController`.
- Звук: свиш удара, импакт попадания, импакт в блок, шаги, смерть врага, смерть игрока. Простой `AudioSource`-подход, без миксера на старте.
- Спринт-анимация: параметр `Speed` сейчас никем не используется (движение — только MoveX/MoveY) — либо ускоряем клип бега множителем по `Speed`, либо добавляем sprint-ветку в дерево.
- (опц.) Cinemachine Impulse на тяжёлый удар; микро-hitstop.

**Acceptance:** 5 минут боя приятны сами по себе: попадания читаются, смерти убедительны, перекат реально спасает.

### Этап 2 — Оружие на карте и прочность (кор-луп)

**Цель:** главная механика игры — оружие как расходник.

**Работы (бывш. Фаза 2 + прочность):**
- `WeaponDefinition` (ScriptableObject): id, displayName, icon, hand-prefab, `WeaponConfig` (light/heavy hitshape), **`maxDurability` + расход прочности за удар**, Animator Override Controller (подмена клипов под оружие), sfx.
- `WeaponHolder` на персонаже (`RightHandSocket` на кости правой руки).
- `WeaponPickup` (**F**): точки оружия на карте, UI-prompt «F: взять Меч».
- Поломка: прочность 0 → vfx/sfx поломки → возврат к кулакам.
- HUD: иконка текущего оружия + полоска прочности.
- `WeaponSpawner`: точки спавна оружия по карте, respawn (заготовка под привязку к волнам в Этапе 3).
- Один активный слот. Несколько слотов — парковка (бывш. Фаза 2.5).

**Acceptance:** подобрал меч → статы и анимации сменились → меч сломался → бежишь искать новый. Петля «успевай искать оружие» ощущается как давление.

### Этап 3 — Волны

**Цель:** бесконечная прогрессия сложности, читаемая структура забега.

**Работы:**
- `WaveManager`: номер волны, количество/HP врагов по кривой от номера волны, пауза между волнами, UI «Волна N».
- `EnemySpawner` подчиняется `WaveManager` (вместо непрерывного таймера).
- Спавн/обновление оружия на карте — в начале волны.
- Счёт: бонус за пережитую волну; итоговый экран смерти показывает волну и убийства.

**Acceptance:** «ещё одну волну» затягивает; сложность растёт бесконечно; смерть даёт понятный итог.

### Этап 3.5 (опц.) — Типы врагов

`EnemyArchetype` (ScriptableObject) + Prefab Variants (бывш. Фаза 3): быстрый/танк/дальник, взвешенный пул в спавнере по номеру волны. Делаем, когда волны с одним типом заработают.

### Этап 4 — Главное меню и гардероб

**Цель:** обёртка игры + кастомизация внешности (бывш. Фазы 4 и 5).

**Работы:**
- Сцена `MainMenu.unity`: Start / Гардероб / Выход. Build Settings.
- `SaveService`: JSON в `Application.persistentDataPath` (D3) — выбранный скин, лучший результат, настройки.
- `SkinDefinition` (ScriptableObject) + перекраска Blink-палитры (`LowPolyCharacterTexture.png` → варианты материалов), минимум 3 скина.
- Гардероб: превью персонажа (RenderTexture/отдельная камера), выбор, сохранение.
- (опц. здесь или в Этапе 5) Топ-10 рекордов с никнеймом.

**Acceptance:** игра стартует из меню; скин выбран в гардеробе → применён в игре → помнится между запусками.

### Этап 5 — Полировка и билд

**Работы (бывш. Фаза 6):** пауза (Esc), настройки (громкость, сенса мыши — подключить `mouseSensitivity` из GameConfig), Quality/иконка/splash, Windows-билд, тест на чужой машине, страница itch.io, кредиты за ассеты.

**Acceptance:** `.exe` играется на чужой машине без Unity и не падает за 10-минутный забег.

### Парковка (возможное будущее, после Этапа 5)

- Классы персонажей (маг / воин / паладин) — потребует систему способностей.
- Онлайн-кооп с друзьями — большая тема (Netcode for GameObjects / Photon), отдельное решение и рефакторинг.
- Разные карты/арены.
- Несколько слотов оружия (бывш. Фаза 2.5).
- Онлайн-таблица рекордов (бывш. Фаза 7).
